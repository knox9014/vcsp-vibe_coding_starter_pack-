# /review — 공개 전 점검

아래 항목을 확인하고 결과를 **신호등**으로 보고하세요. 🟢 괜찮음 / 🟡 고치면 좋음 / 🔴 꼭 고쳐야 함

1. **비밀 정보**: `my-project/` 코드와 git 기록에 실제 API 키·비밀번호·토큰이 있는지.
   - 검색할 때는 `.env` 내용이 화면에 나오지 않도록 `grep -rn --exclude='.env*' …`처럼 제외하세요.
   - `templates/`의 예시, `=` 뒤가 빈 줄, `id-token` 같은 설정 이름은 키가 아니니 무시하세요.
   - `.env`가 `.gitignore`에 있는지 확인.
2. **개인정보·업무 데이터**: 고객 이름, 전화번호, 회사 파일 등이 `my-project/` 안(데이터 폴더 `data/`, `output/` 제외)에 있거나 커밋됐는지. 공개될 `my-project/PROJECT.md`에 남들이 보면 곤란한 내용이 있는지.
3. **동작 확인**: `my-project/PROJECT.md`의 완료된 기능들이 실제로 동작하는지 `/check` 절차(예외 상황 포함)로 확인하기.
4. **데이터가 어디에 저장되나**: `localStorage`를 쓴다면 링크를 연 사람마다 따로 저장된다는 점이 사용자의 목적(혼자 쓰기 / 같이 보기)과 맞는지. 맞지 않으면 🔴.
5. **화면**: 휴대폰 크기에서도 깨지지 않는지 (viewport 메타 태그, 고정 너비 등).
6. **사용자 입력**: 입력값을 그대로 HTML에 넣는 곳(`innerHTML`)이 있으면 🟡로 알리기.
7. **의존성**: `my-project/package.json`이 있으면 `npm audit`으로 심각한 취약점이 있는지 확인 (설치 없이 가능할 때만).
8. **기본 정보**: 페이지 제목(`<title>`)과 `my-project/README.md`가 이 프로젝트에 맞게 바뀌었는지. (루트 `README.md`는 스타터 팩 설명이니 그대로 둬도 됩니다)

🔴가 있으면 그것부터 고칠지 물어보세요. 전부 🟢/🟡면 축하하고, "`/deploy`로 인터넷에 올려볼까요?"라고 제안하세요.
