# /start — 무엇을 만들지 정하고 첫 결과 만들기

사용자는 코딩 초보이고, **무엇을 만들지 정하는 것 자체를 어려워합니다.**
목표는 사용자가 **직접 글을 길게 쓰지 않고, 고르기만 해도** 계획이 완성되는 것입니다.

## 진행 원칙 (모든 단계 공통)

- 질문할 때는 항상 **번호 붙은 선택지 2~4개 + ⭐추천 하나**를 주세요. "1번", "추천대로"만 말해도 넘어가게.
  - Claude Code에서 선택지 질문 도구(AskUserQuestion)를 쓸 수 있으면 그걸 쓰세요. 클릭으로 고를 수 있어 입문자에게 훨씬 쉽습니다.
- 사용자가 "알아서 해줘", "몰라요", "아무거나"라고 하면 ⭐추천으로 정하고 바로 다음 단계로 가세요.
- 사용자가 말한 아이디어가 크면(예: "배달 앱") 깎아내리지 말고 "좋아요! 그중 제일 핵심인 부분부터 만들어 봐요"라고 작은 첫 버전을 제안하세요.
- 사용자가 모르는 단어를 되물으면(예: "다크 모드가 뭐예요?") 한 줄로 설명하고 같은 질문을 이어가세요. 이건 질문 횟수에 세지 않습니다.
- 메시지는 짧게. 아래 단계에서 **"(질문 1번)"이라고 표시된 곳에서만** 사용자에게 묻고, 그 외에는 묻지 말고 진행하세요.

### 질문 횟수 (첫 결과까지 최대 5번)

| 시작 방법 | 질문 순서 | 횟수 |
|---|---|---|
| 처음부터 아이디어를 말함 (예: `/start 고양이 소개 페이지`) | 문장+기능 → 계획 카드 | 2번 |
| 1. 만들고 싶은 게 있음 | 시작 방법 → 문장+기능 → 계획 카드 | 3번 |
| 3. 예시에서 고르기 | 시작 방법 → 예시 → 문장+기능 → 계획 카드 | 4번 |
| 2. 같이 찾기 | 시작 방법 → 두 질문 한 번에 → 아이디어 → 문장+기능 → 계획 카드 | 5번 |

## 1단계: 이어서 할지 확인

- `my-project/PROJECT.md`가 이미 있으면 읽고, "지난번에 ○○를 만들고 있었네요. 이어서 할까요, 새로 시작할까요?"라고 물어보세요. 이어서 하면 `/next` 절차로 넘어가세요. 새로 시작하면 기존 것은 두고 `my-project-2/`를 쓰세요.
- 사용자가 `/start`와 함께(또는 첫마디로) **이미 아이디어를 말했다면** 2단계를 건너뛰고 3단계로 가세요. "시작 방법"을 다시 묻지 마세요.
- 둘 다 아니면 한 줄로 환영 인사 후 2단계로.
- **어느 경우든, 파일을 만들기 전에** 아직 저장 기록이 없으면 AGENTS.md 작업 방식 0번대로 원래 상태를 한 번 저장하세요 (`/save`의 "저장 준비" 포함). 사용자에게는 "시작하기 전에 지금 상태를 저장해 둘게요. 언제든 여기로 돌아올 수 있어요"라고 한 줄만 말하세요.

## 2단계: 시작 방법 고르기 (질문 1번)

> 무엇을 만들지 정해볼게요. 어디에 가까우세요?
> 1. 만들고 싶은 게 있어요 → 한 줄로 말해주세요
> 2. 아직 잘 모르겠어요 → 질문 두 개로 같이 찾아봐요
> 3. 일단 뭐라도 빨리 만들어 보고 싶어요 → 예시 중에 골라요 ⭐처음이라면 추천

**1번**: 사용자의 한 줄을 받아 3단계로. (선택지 도구를 쓴다면 "Other 칸에 한 줄로 적어주세요"라고 안내)

**2번** (질문 1번): 아래 두 질문을 **한 번에** 물어보세요. 선택지 도구는 질문 여러 개를 한 번에 보낼 수 있습니다. 각 질문에 ⭐추천을 붙이고, "몰라요"면 ⭐추천 값을 쓰세요.
- "요즘 귀찮거나, 자꾸 까먹거나, 반복하는 일은?" — 보기: 일·가게에서 반복하는 일 / 공부·운동 기록 ⭐ / 돈·약속 관리 / 직접 쓰기
- "좋아하는 것이나 관심사는?" — 보기: 게임 / 음식·카페 ⭐ / 운동·여행 / 직접 쓰기

그다음 (질문 1번) 두 답을 섞은 **맞춤 아이디어 3개**를 고르게 하세요. 각각 한 줄 설명 + 난이도(⭐~⭐⭐⭐), 가장 쉬운 하나에 ⭐추천.
> 예) 가게 + 까먹음 → 1. 손님별 도장 카드 — 전화번호 뒷자리로 찾기 (⭐⭐) ⭐추천 / 2. 오늘의 메뉴판 페이지 (⭐) / 3. 주문 메모 정리 도구 (⭐⭐)
- 추천은 "가장 쉬운 것"보다 **사용자의 실제 고민을 해결하는 것 중 가장 쉬운 것**으로 고르세요.

**3번** (질문 1번): `docs/06-첫-프로젝트-아이디어.md`의 "⭐ 30분이면 첫 결과가 보이는 것"을 번호로 보여주고 고르게 하세요. 사용자가 **전부 마음에 안 든다**고 하면 "그럼 만들고 싶은 걸 한 줄로 말해주세요"라고 1번 경로로 바꾸세요.

## 3단계: 한 문장 + 기능 고르기 (질문 1번)

**한 메시지에** 아래 두 가지를 보여주고 한 번만 물어보세요.

1. AI가 채운 **한 문장 초안**
   > 📌 **[누구]**를 위한, **[무엇을 하는]** **[결과물 종류]**
   > 예) **우리 카페 단골 손님**을 위한, **전화번호 뒷자리로 도장을 모으는** **도장 카드 페이지**
   - "누가 쓰나요?"는 따로 묻지 말고 아이디어에 맞게 채우세요 (기본값 "나", 중고거래·투표처럼 여럿이 쓰는 아이디어면 "친구들", 가게면 "손님").
   - 결과물 종류: 웹페이지 / 게임 / 자동화 스크립트(엑셀·파일 정리 등) 중 아이디어에 맞는 것.
2. 기능 후보 **5~6개** 체크리스트. **딱 3개에 ⭐이번에**, 나머지는 **⏭️ 나중에**

질문: "이대로 할까요?" — 선택지 예: ⭐추천대로 / 더 간단하게(⭐ 중 2개만) / 다른 조합(번호로 말하기) / 문장을 고치고 싶어요

- 로그인, 결제, 여러 명이 동시에 쓰기, 알림은 기본적으로 ⏭️ 나중에 두고, 왜 나중에인지 한 줄로 설명하세요 ("처음엔 어렵고 안전하게 만들기 까다로워요"). 언젠가 하고 싶다면 "첫 버전이 완성되면 Supabase 같은 도구로 이어서 할 수 있어요"라고 길을 열어 두세요.
- 사용자가 고른 기능이 3개를 넘으면 **한 번만** "처음 버전은 3개만 해보고, 나머지는 완성 후에 추가해요"라고 제안하세요. 그래도 원하면 존중하세요: 전부 할 일 목록에 넣되 순서만 쉬운 것부터 정하고 넘어가세요. 다시 설득하지 마세요.

## 4단계: 계획 카드 확인 (질문 1번)

**한 메시지에** 계획 카드와 **미리보기**를 보여주고 한 번 물어보세요.

```
📌 만들 것: 우리 카페 단골 손님을 위한, 전화번호 뒷자리로 도장을 모으는 도장 카드 페이지
✅ 이번에 만들 것: ① 번호로 손님 찾기/추가 ② 도장 찍기 ③ 10개면 축하
⏭️ 나중에: 쿠폰 발급, 여러 기기에서 같이 보기
🧱 순서: 1. 번호 입력하면 그 손님 카드가 보이고 도장 찍힘  2. 10개면 축하  3. 기록 백업 버튼
💾 기록은 이 컴퓨터 브라우저에만 저장돼요 (다른 기기에선 안 보이고, 브라우저 기록을 지우면 사라질 수 있어서 백업 버튼을 넣어요)
```

- 데이터를 기록하는 웹페이지라면 계획 카드에 "💾 기록은 어디에 저장되는지" 한 줄을 꼭 넣으세요 (AGENTS.md의 localStorage 안내).

**웹페이지·게임이면**: 첫 화면을 **글자 그림(ASCII)으로 스케치**해 함께 보여주고, 질문은 분위기 고르기로 하세요. 분위기를 고르면 "이 계획대로 시작"에 동의한 것으로 봅니다.

```
┌──────────────────────────┐
│   ☕ 단골 도장 카드        │
│   ● ● ● ○ ○              │
│   ○ ○ ○ ○ ○              │
│   [ 도장 찍기 ]            │
└──────────────────────────┘
```
> 이렇게 만들어 볼게요! 분위기만 골라주세요.
> 1. 깔끔한 흰색 ⭐추천  2. 귀여운 파스텔  3. 어두운 화면(다크 모드)  4. 계획을 바꾸고 싶어요

**자동화 스크립트면**: 화면 스케치·분위기 대신 **결과 예시**(예: 합쳐진 표의 처음 몇 줄)를 보여주고 "이대로 시작할까요?"(⭐네 / 계획을 바꾸고 싶어요)를 물으세요.
- 회사·고객 데이터를 다룬다면 함께 알려주세요: "AI가 파일을 열거나 실행 결과를 보면 그 내용이 AI 서비스로 전송돼요. 처음엔 가짜 샘플 파일(`my-project/sample/`)로 만들고, 진짜 파일은 `my-project/data/`에 넣으세요. `data/`는 GitHub에도 안 올라가요."

"계획을 바꾸고 싶어요"를 고르면 무엇을 바꿀지 듣고 카드를 고쳐서 다시 보여주세요. (이건 횟수에 세지 않습니다)

## 5단계: 계획 파일 저장

묻지 말고 진행하세요.
- `templates/PROJECT_BRIEF.md`를 복사해 `my-project/PROJECT.md`로 만들고 계획 카드, 분위기, 스케치(또는 결과 예시)로 채우세요.
- `my-project/README.md` 안내문은 지우지 말고 이 프로젝트의 짧은 소개(한 문장 + 여는 법)로 바꿔 쓰세요.
- 할 일마다 `→ 확인: (어떻게 되면 성공인지)`를 붙이세요. 첫 할 일은 **눈에 보이는 결과 + 핵심 동작 하나**입니다.
  - 웹·게임: 화면이 보이고 버튼 하나는 눌러서 반응해야 해요 (정지 화면만 만들지 마세요).
  - 스크립트: 샘플 파일로 한 번 실행해 결과가 나와야 해요.
- 기술 선택은 AGENTS.md의 "기술 선택 기본값"을 따르고, 사용자에게 따로 묻지 마세요.
- "앞으로 만드는 건 전부 `my-project` 폴더 안에 생겨요"라고 한 줄로 알려주세요.

## 6단계: 첫 결과물

- 할 일 1번만 만드세요. 스케치(또는 결과 예시)와 고른 분위기를 따르세요. 가능하면 직접 실행해 확인하세요.
- 여는 법/실행하는 법을 사용자의 컴퓨터에 맞게 알려주세요.
  - 웹: "파일 탐색기(Mac은 Finder)에서 이 폴더 → `my-project` → `index.html` 더블클릭". 편집기 화면이 보인다면 "왼쪽 파일 목록에서" 찾아도 된다고 덧붙이세요.
  - 스크립트: 샘플 파일로 AI가 직접 실행해 결과를 보여주고, 결과 파일 위치를 알려주세요. 사용자가 다음에 혼자(진짜 데이터로) 돌릴 수 있도록 **더블클릭 실행 파일**을 만들어 줄지 제안하세요. 만드는 법은 AGENTS.md "사용자의 컴퓨터" 표를 따르세요 (Mac은 `chmod +x` 필수).
- "스케치랑 비슷하게 나왔나요? 바꾸고 싶은 게 있으면 말해주세요"라고 물어보세요.
- 잘 되면 `my-project/PROJECT.md`에서 **할 일 1번을 체크**하고, **현재 상태**와 **실행 방법**을 채우세요. (다음 대화의 AI가 이것만 보고 이어갑니다)

## 7단계: 첫 저장

- "잘 되니까 여기까지 저장할게요(게임 세이브 포인트 같은 거예요)"라고 하고 `/save` 절차대로 저장하세요. 1단계에서 저장 준비를 이미 했으니 따로 묻지 않아도 됩니다.
- 마지막으로 이렇게 안내하세요:
  - "다음 기능은 `/next`, 오늘 그만할 땐 `/wrap` 하면 돼요."
  - 완성 예시가 궁금하면 `examples/water-counter/`를 열어보라고 알려주세요.
