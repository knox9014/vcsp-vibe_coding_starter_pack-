# /start — 첫 프로젝트 시작하기

사용자는 코딩 초보입니다. 아래 순서를 지키되, 대화는 가볍고 따뜻하게 진행하세요.

## 1단계: 인사 & 이미 진행 중인지 확인

- `my-project/PROJECT.md`가 이미 있으면 읽고, "지난번에 ○○를 만들고 있었네요. 이어서 할까요, 새로 시작할까요?"라고 물어보세요.
- 없으면 한 줄로 환영 인사 후 2단계로.

## 2단계: 아이디어 인터뷰 (한 번에 질문 1~2개씩)

다음을 차례로 물어보세요. 사용자가 막막해하면 `docs/06-첫-프로젝트-아이디어.md`에서 예시 3개를 골라 보여주세요.
**질문마다 추천 답을 함께 제시**해서 사용자가 "네"만 해도 넘어갈 수 있게 하세요.

1. 무엇을 만들고 싶나요? (한 문장이면 충분)
2. 누가 쓰나요? (나 혼자 / 친구들 / 아무나)
3. 꼭 필요한 기능은? 사용자의 답을 바탕으로 **핵심 기능 최대 3개**와 **"이번엔 안 할 것" 목록**(로그인, 결제 등)을 제안하고 확인받으세요.
4. 참고하고 싶은 느낌이나 사이트가 있나요? (없어도 OK. 스크린샷을 붙여넣어도 돼요)

## 3단계: 계획 파일 만들기

- `templates/PROJECT_BRIEF.md`를 복사해 `my-project/PROJECT.md`로 만들고, 답변으로 채우세요. (`my-project/README.md` 안내문은 지워도 됩니다)
- 사용자에게 "앞으로 만드는 건 전부 `my-project` 폴더 안에 생겨요"라고 한 줄로 알려주세요.
- 할 일 목록은 **3~5개의 아주 작은 단계**로 쪼개세요. 첫 단계는 반드시 "화면에 뭔가 보이기"여야 합니다.
- 각 할 일 끝에 `→ 확인: (어떻게 되면 성공인지)`를 붙이세요. 예: `→ 확인: 버튼을 누르면 숫자가 1 올라감`
- 기술 선택은 AGENTS.md의 "기술 선택 기본값"을 따르세요.
- 완성된 계획을 5줄 이내로 요약해 보여주고 "이대로 시작할까요?"라고 확인받으세요.

## 4단계: 첫 결과물

- 할 일 1번만 만드세요. (보통 `my-project/index.html` 하나)
- 확인 방법을 단계별로 알려주세요. 예: "왼쪽 파일 목록에서 `my-project` 폴더 → `index.html` 더블클릭 → 브라우저에서 열려요"
- 보이는 게 마음에 드는지 물어보세요.

## 5단계: 첫 저장

- 아직 git 저장소가 아니면 `git init`을 하세요.
- 커밋이 뭔지 한 줄로 설명하고("게임 세이브 포인트 같은 거예요"), 동의하면 첫 커밋을 만드세요.
- 마지막으로 이렇게 안내하세요:
  - "다음 기능은 `/next`, 오늘 그만할 땐 `/wrap` 하면 돼요."
  - 완성 예시가 궁금하면 `examples/water-counter/`를 열어보라고 알려주세요.
