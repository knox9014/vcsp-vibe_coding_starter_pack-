# /save — 체크포인트 저장

## 1. 처음 한 번만: 저장 준비

1. `git --version`으로 git이 있는지 확인하세요.
   - 없으면: "저장 기능을 쓰려면 Git이라는 프로그램이 필요해요"라고 하고 설치를 안내하세요. (Windows: git-scm.com에서 받아 기본값으로 설치 / Mac: 터미널이 "개발자 도구 설치" 창을 띄우면 '설치' 클릭) 설치 후 다시 `/save` 하라고 하세요.
2. git 저장소가 아니면 `git init -b main` 후 `git config core.quotepath false`(한글 파일 이름이 깨져 보이지 않게)를 실행하고 "이 폴더의 변경 기록을 시작했어요"라고 알려주세요.
3. `git config user.name`과 `git config user.email`이 비어 있으면 커밋이 실패합니다. 미리 설정하세요.
   - "저장 기록에 남길 이름을 알려주세요 (별명도 돼요)"라고 **한 번만** 물어보세요.
   - 이메일은 묻지 말고 `이름@example.com` 같은 가짜 주소로 이 폴더에만 설정하세요: `git config user.name "이름"` / `git config user.email "…@example.com"`
   - "나중에 GitHub에 올릴 때 바꿀 수 있어요"라고 한 줄 덧붙이세요.

## 2. 저장하기

1. `git status`로 바뀐 파일을 확인하세요. 바뀐 게 없으면 "이미 다 저장돼 있어요!"라고 하고 끝.
2. **비밀 정보 점검**: `.env`, 키·토큰·비밀번호처럼 보이는 값이 커밋될 파일에 있으면 멈추고 알려주세요. `.env`가 `.gitignore`에 있는지도 확인하세요.
3. **업무·개인 데이터 점검**: 고객 명단, 회사 엑셀/CSV, 전화번호·주소 같은 개인정보가 들어 있는 파일이 커밋 대상이면 멈추세요. `my-project/data/`(GitHub에 안 올라가는 폴더)로 옮기자고 제안하세요.
4. `git add -A` 후, 무엇이 바뀌었는지 **한국어 한 줄**로 커밋 메시지를 쓰세요. 예: `할 일 추가 버튼 만들기`
   - 이 폴더의 **첫 저장**이면 스타터 팩 파일도 함께 저장되므로 `시작: 스타터 팩 + 첫 화면`처럼 쓰세요.
5. 결과를 이렇게 알려주세요:
   - "💾 저장했어요: ○○○"
   - "문제가 생기면 `/undo`로 언제든 여기로 돌아올 수 있어요."

GitHub에 올리기(push)는 사용자가 따로 요청할 때만 하세요.
