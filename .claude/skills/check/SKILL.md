# /check — 제대로 되는지 확인하기

이 단계에서는 **고치지 말고 보고만** 하세요. 고칠지는 사용자가 정합니다.

## 1. 무엇을 확인할지 정하기

- `my-project/PROJECT.md`의 가장 최근 완료/진행 중 항목과 그 "→ 확인:" 기준을 읽으세요.
- 없으면 가장 최근에 바뀐 파일(`git diff`, `git log -3`)을 기준으로 하세요.

## 2. 직접 실행해 보기

- 실행할 수 있는 환경이면(예: 이미 설치된 Playwright, node/python) 직접 실행해서 확인하세요. 확인만을 위해 새 도구를 설치하지 마세요.
- 직접 실행할 수 없으면 사용자에게 **3단계 이내의 확인 체크리스트**를 주고 결과를 알려달라고 하세요.

## 3. 예외 상황 (프로젝트에 해당하는 것만)

**웹페이지·게임**
- 아무것도 입력하지 않고 버튼 누르기
- 아주 긴 글자 / 특수문자·이모지 입력
- 버튼 여러 번 빠르게 누르기
- 새로고침 후에도 데이터가 남는지 (저장 기능이 있다면)
- 휴대폰 화면 너비(약 375px)에서 깨지지 않는지
- 브라우저 콘솔에 빨간 에러가 없는지

**데이터 처리·자동화 스크립트**
- 입력 폴더가 비었을 때 (조용히 0을 내지 말고 알려주는지)
- 파일 한글이 깨지는지 (엑셀에서 저장한 CSV는 보통 `cp949` 인코딩)
- 열 이름이 조금 다르거나, 빈 줄·빈 칸이 있는 파일
- 숨김 파일(`.DS_Store` 등)이나 엉뚱한 파일이 섞여 있을 때
- 결과 숫자 하나를 사용자가 엑셀로 직접 계산한 값과 비교해 보기

## 4. 보고

표로 정리하세요:

| 확인한 것 | 결과 | 어떻게 확인했나 |
|---|---|---|
| 추가 버튼 | ✅ | 직접 눌러봄 |
| 빈 입력 | ⚠️ 빈 항목이 추가됨 | 빈 칸으로 눌러봄 |

마지막에 "가장 먼저 고치면 좋을 것 1~2개"를 제안하고, "`/fix`로 고칠까요?" 물어보세요. 모두 ✅면 "`/save` 할까요?"라고 제안하세요.
